# 内容编写规范

> 这个产品 80% 是内容，20% 是工程。内容质量决定一切。

## 一、新增一卦的流程

1. 在 `content/hexagrams/` 下创建 `NN-name.ts`（如 `04-meng.ts`）
2. 参照 `01-qian.ts` 的结构，导出一个 `Hexagram` 类型的对象
3. 在 `content/hexagrams/index.ts` 中 import 并加入 `ALL_HEXAGRAMS`
4. 运行 `npm run typecheck` 确认类型无误

## 二、字段要求

### 必填字段

| 字段           | 要求                                    |
| -------------- | --------------------------------------- |
| `number`       | 1-64，按通行本卦序                      |
| `name`         | chinese + pinyin + english 三个都要填   |
| `trigrams`     | 上下卦（八经卦名）                      |
| `binary`       | 6 位 0/1，从上到下，1=阳 0=阴           |
| `judgment`     | 卦辞原文 + 现代释读（200-400 字）       |
| `image`        | 象传原文 + 现代释读（100-200 字）       |
| `features`     | 全部 6 个维度都要填                     |
| `keywords`     | 至少 10 个中文关键词                    |
| `themes`       | 至少 4 个主题标签                       |
| `appliesWhen`  | 至少 3 条适用情境（自然语言）           |
| `antiPatterns` | 至少 2 条常见误读                       |
| `yao`          | 6 爻全部填写                            |
| `parallels`    | 至少 1 条西哲 + 2 条现代案例 + 1 条文学 |

### 每一爻的要求

| 字段            | 要求                           |
| --------------- | ------------------------------ |
| `name`          | "初九" / "六二" 等，按传统命名 |
| `text`          | 爻辞原文                       |
| `modernReading` | 150-300 字现代释读             |
| `scenario`      | 一段具体的现代场景描述         |
| `actionable`    | 3-5 条可执行建议               |
| `indicators`    | 3-5 条"你处此爻的征象"         |

## 三、内容原则

### 1. 义理派立场

- 不使用"天命"、"注定"、"命中"等宿命论措辞
- 不暗示卦象能预测未来
- 把卦当作"情境模式"而非"天意指示"

### 2. 现代释读的要求

- **具体**：不说"要谨慎"，说"在这个阶段做决策前，给自己 48 小时冷静期"
- **可证伪**：避免"怎么理解都对"的万能句式
- **有方向性**：明确推荐做什么或不做什么，不做两面人

### 3. 跨文化锚点

- 西方哲学引用要准确（写出思想家 + 具体概念 + 出处）
- 现代案例要注明结局（成 / 败 / 杂），不只选成功案例
- 文学影视举例要具体到情节而非笼统提及

### 4. 反模式

- 每卦至少写 2 条"这样理解是错的"
- 用于防止用户把易经当万能鸡汤

## 四、文风

- **克制**：不煽情，不说教，不用感叹号
- **精确**：每句话都应能被追问"你这么说的依据是什么"
- **人话**：古文必须翻译，术语必须解释
- **不矫情**：不为了押韵而牺牲准确度

## 五、引号规范

- 字符串内嵌引号统一用中文方头括号 `「」`
- 不要在 TS 字符串内使用英文双引号 `""`，会破坏语法解析
- 单引号 `''` 用于非正式强调可以保留
